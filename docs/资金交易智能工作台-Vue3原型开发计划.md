# 资金交易智能工作台 Vue3 原型开发计划

> 目标：基于 `docs` 中的 PRD、产品描述、交互规格和线框图，按照 `TKtheme` 设计要求，交付一个可交互、可演示、可校验的 Vue3 + Vite 网页原型。

## 1. 开发目标

首版原型聚焦交易员的一屏闭环：查看任务缺口、匹配行情、打开聊天、确认成交、快捷分配、转全屏矩阵、回写左栏台账。

原型不接真实后端，使用 mock 数据模拟行情、账户、聊天、成交和分配结果；交互行为、状态反馈、布局密度和视觉规范需要尽量接近真实产品。

## 3. 技术方案

| 项目 | 方案 |
| --- | --- |
| 前端框架 | Vue3 |
| 构建工具 | Vite |
| 语言 | TypeScript |
| 样式 | 原生 CSS + TKtheme CSS Variables |
| 状态管理 | Vue `ref` / `computed` / `reactive`，首版不引入 Pinia |
| 数据来源 | 本地 mock 数据 |
| 图标 | 优先使用已有图标库或轻量 SVG 图标组件 |
| 验证方式 | 本地运行、浏览器交互检查、构建检查、截图走查 |

建议将 Vue 原型放在独立目录，例如：

```text
newworkspace/trading-workbench-vue/
```

这样可以避免影响当前 React/Vite 工程，同时便于后续独立演示和迁移。

## 5. 分步计划、Checklist 与校验规则

### Step 0. 范围确认与工程准备

开发内容：

- [ ] 确认 Vue 原型目录，建议使用 `newworkspace/trading-workbench-vue/`。
- [ ] 初始化 Vue3 + Vite + TypeScript 工程。
- [ ] 配置基础脚本：`dev`、`build`、`preview`。
- [ ] 引入 `TKtheme/theme.css`。
- [ ] 建立 `src/styles/app.css` 承载原型局部样式。

校验规则：

- [ ] 本地开发服务可以启动。
- [ ] 页面能读取 `--tk-color-brand-primary` 等 CSS 变量。
- [ ] 构建命令无 TypeScript 或 Vite 报错。
- [ ] 不修改现有 PRD、线框图和交互规格文档。

### Step 1. 建立 mock 数据与状态模型

开发内容：

- [ ] 新建账户台账 mock 数据，包含账户、期限、未出、完成度、保本利率、状态。
- [ ] 新建行情报价 mock 数据，包含发送机构、期限报价、限户要求、最优/次优状态。
- [ ] 新建历史聊天 mock 数据，包含对手、最新消息、未回复状态、关联报价。
- [ ] 新建成交和快捷分配 mock 数据。
- [ ] 定义全局 UI 状态：当前账户、当前报价、聊天弹窗、分配矩阵、中栏浮框。

校验规则：

- [ ] mock 字段能覆盖 PRD P0 展示需求。
- [ ] 保本预警、已完成、未回复、最优、次优等状态均有样例。
- [ ] 金额单位在展示层统一为“亿元”。
- [ ] mock 数据不使用真实客户、真实交易和敏感信息。

### Step 2. 顶栏与三栏布局

开发内容：

- [ ] 实现顶栏，展示工作台名称、DR007、资金情绪四值、松紧结论、账户切换、通知。
- [ ] 实现三栏布局，默认比例参考左 22%、中 28%、右 50%。
- [ ] 左栏为任务核心区，中栏为投研/行情摘要区，右栏为行情和聊天主战场。
- [ ] 预留浮层容器，用于聊天弹窗、中等浮框和全屏矩阵。

校验规则：

- [ ] 1920 x 1080 下首屏无需滚动即可看到顶栏与三栏主体。
- [ ] 顶栏在聊天弹窗和矩阵打开前后保持可感知。
- [ ] 三栏间距、字号、行高符合 TKtheme 的紧凑工作台风格。
- [ ] 页面不出现营销式 hero、大面积装饰色块或卡片堆叠。

### Step 3. 左栏任务模块

开发内容：

- [ ] 实现试算利率输入区。
- [ ] 实现交易单台账精简表。
- [ ] 支持账户行单击选中。
- [ ] 支持保本预警、已完成、选中、hover 状态。
- [ ] 实现待分配额度池，支持点击条目打开聊天。
- [ ] 实现“展开矩阵”入口。

校验规则：

- [ ] 账户行选中后视觉状态明确，并能驱动右栏行情高亮。
- [ ] 保本预警不能只依赖颜色，需要同时有边框、标识或强调形态。
- [ ] 已完成账户行淡化但仍可点击。
- [ ] 待分配条目至少展示对手、金额、成交利率、时间、来源。
- [ ] 台账行高度紧凑，主要字段在 1366 宽度下不相互遮挡。

### Step 4. 中栏投研与行情摘要模块

开发内容：

- [ ] 实现资金面、AI 判断、基准价格、交易所回购、NCD、机构统计等摘要卡。
- [ ] 摘要卡展示关键数值、更新时间、数据状态。
- [ ] 点击摘要卡打开中等浮框。
- [ ] 支持浮框关闭、Esc 关闭、点击外部关闭。
- [ ] 实现数据暂缺、延迟、取数失败状态。

校验规则：

- [ ] 摘要卡默认态有可读数据，不只是入口按钮。
- [ ] 中等浮框不覆盖右栏主战场。
- [ ] 浮框打开后焦点落在浮框内第一个可操作控件。
- [ ] 数据异常时卡片保留原位，布局不跳动。
- [ ] 极窄宽度下中栏可以收缩为窄边摘要或图标列。

### Step 5. 右栏行情与历史聊天模块

开发内容：

- [ ] 实现层级切换：1 级 / 2 级。
- [ ] 实现筛选条：期限、发送机构、金额、利率、仅看相同交易对手。
- [ ] 实现期限标签：R001、R007、R014、R021、R028。
- [ ] 实现行情分组：利率地方、存单商金、信用。
- [ ] 实现行情表格和期限报价单元格。
- [ ] 实现历史聊天对手 Tab：未回复、已回复、全部。
- [ ] 支持行情单元格单击打开聊天，双击模拟快捷询价。

校验规则：

- [ ] 左栏账户选中后，右栏匹配报价高亮并可过滤。
- [ ] 最优/次优标签清晰但不喧宾夺主。
- [ ] 行情单元格点击后聊天弹窗顶部带入报价摘要。
- [ ] 历史聊天对手点击后打开对应会话。
- [ ] 双击报价后出现“已发送”瞬时状态。
- [ ] 表格横向内容不溢出右栏容器。

### Step 6. 聊天弹窗与快捷分配

开发内容：

- [ ] 实现聊天弹窗，包含标题栏、报价摘要、消息流、输入框、快捷操作。
- [ ] 支持拖拽标题栏移动弹窗，限制在视口内。
- [ ] 支持关闭按钮和 Esc 关闭。
- [ ] 点击“确认成交”后展开快捷分配面板。
- [ ] 快捷分配只展示可分配账户。
- [ ] 支持 AI 预填、手动编辑金额、保存分配、挂入待分配、转全屏矩阵。

校验规则：

- [ ] 从行情和历史聊天进入弹窗时，上下文正确。
- [ ] 快捷分配面板不展示不可分配账户。
- [ ] 分配金额修改后差额实时更新。
- [ ] 保存后左栏台账的未出、完成度、状态同步变化。
- [ ] 关闭未保存的快捷分配时出现二次确认。
- [ ] 弹窗层级低于全屏矩阵，高于三栏内容。

### Step 7. 全屏分配矩阵

开发内容：

- [ ] 实现全屏矩阵覆盖层。
- [ ] 支持从左栏展开、待分配条目、聊天快捷分配进入矩阵。
- [ ] 实现账户字段列、对手额度列、分配格子。
- [ ] 支持格子点击编辑、键盘 Enter 保存、Esc 取消。
- [ ] 实现横向对手额度差额和纵向账户未出差额。
- [ ] 支持 AI 自动分配草案、清空、保存分配、关闭。

校验规则：

- [ ] 矩阵打开时覆盖三栏，并高于聊天弹窗。
- [ ] 账户列和对手额度头部在视觉上保持冻结感。
- [ ] 差额为 0、待分配、超分配三类状态可区分。
- [ ] 保存分配后回写左栏台账。
- [ ] Esc 可关闭矩阵，若有未保存修改需要确认。
- [ ] 大表格滚动时表头、行列对齐不漂移。

### Step 8. 全局键盘、浮层层级与响应式

开发内容：

- [ ] 实现 Esc 逐层关闭：聊天弹窗、中等浮框、全屏矩阵。
- [ ] 实现 Tab / Shift+Tab 在当前浮层内移动焦点。
- [ ] 实现 Enter 对当前主操作的触发，避免和多行输入冲突。
- [ ] 实现 hover、selected、disabled、danger、success 等状态。
- [ ] 实现中栏响应收缩策略。
- [ ] 检查 1920、1440、1366 三档宽度。

校验规则：

- [ ] 同时只允许一个全屏矩阵。
- [ ] 聊天弹窗可与矩阵共存，但矩阵在更高层。
- [ ] 没有浮层时 Esc 不产生误操作。
- [ ] 1366 宽度下核心路径仍可操作。
- [ ] 所有按钮和输入控件可通过键盘聚焦。

### Step 9. TKtheme 视觉走查

开发内容：

- [ ] 检查主色、状态色、文字色是否来自 TKtheme 变量。
- [ ] 检查字体是否使用 `PingFang SC`, `Microsoft YaHei`, `Helvetica Neue`, Arial, sans-serif。
- [ ] 检查深色工作台是否使用反白文字 token。
- [ ] 检查白底弹窗是否使用 TKtheme 弹窗规范。
- [ ] 检查表格、列表、按钮、输入框、Tab、开关的一致性。

校验规则：

- [ ] 业务组件中不直接硬编码主题色，除非 TKtheme 缺少对应 token。
- [ ] 主按钮、Tab 指示线、开关开启态使用统一蓝色体系。
- [ ] 危险、成功、警告状态使用语义色，不混用多个红色或绿色。
- [ ] 弹窗圆角控制在 0 到 4px。
- [ ] 字号不使用视口宽度动态缩放。
- [ ] 文字不遮挡、不溢出按钮和表格单元格。

### Step 10. 构建、验收与交付

开发内容：

- [ ] 执行开发环境走查。
- [ ] 执行生产构建。
- [ ] 用浏览器完成核心路径录屏或截图走查。
- [ ] 记录已完成 checklist。
- [ ] 记录未接真实接口、未覆盖业务规则和后续风险。
- [ ] 输出运行说明。

校验规则：

- [ ] `npm run build` 或等效构建命令通过。
- [ ] 页面无明显控制台错误。
- [ ] 核心闭环可连续演示，不需要刷新页面。
- [ ] 所有 P0 交互都有可见反馈。
- [ ] 文档中记录的已知限制与实际原型一致。

## 7. 风险与待确认项

| 风险 / 待确认 | 影响 | 原型处理方式 |
| --- | --- | --- |
| 多会话聊天策略未最终确认 | 影响弹窗替换还是多弹窗并存 | 首版采用单弹窗替换，代码预留配置 |
| 准入 / 额度 / 质押校验接口未接入 | 影响真实分配阻断 | 首版使用 mock 校验结果 |
| 行情和聊天实时推送未接入 | 影响数据刷新体验 | 首版用本地状态模拟刷新和瞬时反馈 |
| 金额精度和单位待确认 | 影响矩阵输入和差额计算 | 首版展示统一用“亿元”，内部用 number |
| 中栏极窄态细节需设计确认 | 影响小屏或缩放体验 | 首版实现窄边摘要，后续再视觉精修 |
