# 资金实时行情看板 UI/UX 与 src 实现对比说明

## 1. 对比结论

截图对应的主界面来自 `src/app/App.tsx`，入口由 `src/main.tsx` 直接加载 `App`。`src/app/components/CenterPanel.tsx`、`RightPanel.tsx`、`LeftPanel.tsx`、`MarketChartPage.tsx` 也是行情相关组件，但当前主入口没有引用它们，更像早期原型或备用实现。因此，本说明以 `App.tsx` 为准。

总体来看，截图中的深色三栏看板、左侧行情表、右侧趋势图、NCD 卡片与 `App.tsx` 的实际实现基本一致。主要差异在于：部分按钮只有视觉样式，没有业务回调；数据主要是静态数组或本地随机序列；下载、发送、接口态、加载态、空态、失败态尚未真正闭环。

## 2. 实现入口与页面框架

| 项目 | 截图表现 | src 实现 | 对比结论 |
|---|---|---|---|
| 应用入口 | 资金实时行情看板 | `src/main.tsx` 引入 `src/app/App.tsx` | 一致 |
| 页面结构 | 深色主题，高密度三栏看板 | `App` 使用顶部栏 + 左栏 + 中栏 + 右栏 | 一致 |
| 栏宽调整 | 截图中能看到栏间边界 | `ColumnSplitter` 支持左右栏拖拽，并写入 `localStorage` | 实际实现更完整 |
| 顶部筛选 | 金额、利率区间展示 | `RangeFilterField` 只是展示型组件，没有输入回调 | 视觉存在，交互不足 |
| 数据来源 | 看起来像实时行情 | 大量数据来自静态数组、`randomWalk`、`Math.random` | 目前是前端模拟数据 |
| 悬浮球 | 截图未完整体现 | `FloatingBall` 可拖拽，但无业务动作 | 额外交互，需要确认是否保留 |

关键代码位置：

- `src/main.tsx`
- `src/app/App.tsx`：`App`、`TopBar`、`ColumnSplitter`、`FloatingBall`

## 8. 设计与实现差异总结

1. 截图里的核心视觉已经在 `App.tsx` 中实现，深色主题、卡片边框、蓝色选中态、红绿涨跌语义基本统一。
2. 图表交互比截图说明更复杂，尤其是“加权价格走势”和“匿名成交走势图”之间存在共享叠加品种状态。
3. 表格操作的视觉完成度较高，但下载、发送多数还没有实际行为。
4. 手工输入是当前最完整的业务交互之一，但仍停留在本地状态层。
5. 当前项目没有真实行情接口、WebSocket、轮询服务或错误态处理，不能视为真正实时行情系统。
6. `src/app/components` 下还有旧版白底组件，和当前截图不是同一套交互体系，容易造成维护混淆。

## 9. 后续建议

| 优先级 | 建议 | 原因 |
|---|---|---|
| P0 | 明确 `App.tsx` 为当前唯一主实现，归档旧组件 | 防止后续改错文件 |
| P0 | 给所有“下载”“发送”按钮补真实回调或禁用态 | 当前视觉暗示可操作，但实际无反馈 |
| P0 | 接入真实数据源或统一 mock 服务层 | 当前数据分散在静态数组和随机函数里 |
| P1 | 顶部金额 / 利率筛选改为真实输入控件 | 现在只展示，不筛选 |
| P1 | 明确匿名成交叠加品种是否应影响加权价格走势 | 当前跨模块联动不够直观 |
| P1 | 补加载、空数据、失败、权限不足状态 | 交易类看板必须有明确状态反馈 |
| P2 | NCD 一级趋势增加期限选择 | 当前趋势图固定 1M |
| P2 | 对表格数字列做更严格的对齐和状态提示 | 提升高频扫描效率 |
