# 开发计划

按"先低风险高收益、后结构性改动"分四阶段推进,每阶段独立可发布,便于回滚和增量验收。

------

## Phase 1 · 视觉密度与扫读优化(预计 1.5 天 / 5 个 commit)

无结构调整,纯样式与小组件级改动,风险最低。

| 序号 | 任务                                                         | 文件                                                        | 验收                        |
| ---- | ------------------------------------------------------------ | ----------------------------------------------------------- | --------------------------- |
| 1.1  | 单元格三段式结构:期限码灰色小字 → 总额加粗大字 → 已分/待分色分(蓝/橙) | `TaskOverviewMatrix.vue`、`app.css` `.task-overview-amount` | 单元格三行清晰,数字字号≥14  |
| 1.2  | 空单元格轻量化:`—` 改 4px 圆点,空主导列宽 56px               | 同上                                                        | 行密度提升 ~20%             |
| 1.3  | 行/列头视觉差:列头左上色块+类型+数量徽章;行头左侧 4px 色条   | 同上                                                        | 十字定位一眼可见            |
| 1.4  | 行情卡片价格行加粗:`15亿 @1.68` 单独行 `font-family-number` 18px | `OpponentCard.vue`                                          | 价格成视觉锚点              |
| 1.5  | 等级 chip 退化为左侧 4px 色条(1 级深、2 级浅)                | `OpponentCard.vue`、`app.css`                               | 卡片右上角不再有 `1级` 角标 |

**里程碑**:不动布局,信息层级先立起来。

## Phase 2 · 操作可达性(预计 2 天 / 4 个 commit)

新增组件、监听 hover 与点击事件解耦,有交互回归风险,需手测。

| 序号 | 任务                                                         | 文件                                                         | 备注                         |
| ---- | ------------------------------------------------------------ | ------------------------------------------------------------ | ---------------------------- |
| 2.1  | 单元格底部 2px 进度条(`allocated/total`,完成色变绿)          | `TaskOverviewMatrix.vue`、`useTaskOverviewMatrix.ts`(确认 allocated 数据已存在) | 完成度 100% 加 ✓             |
| 2.2  | 粘性 `小计` 行加阴影、加深底色、字号 +1;`展开矩阵` 按钮挪入该行右端 | `TaskOverviewMatrix.vue`、`app.css`                          | 顺手收掉旧位置的按钮         |
| 2.3  | 行情卡片 hover 浮出 `回价 / 带入矩阵 / 静音` 按钮(右上),与卡片整体点击解耦 | `OpponentCard.vue`、`MarketPanel.vue`(事件)                  | 注意键盘可达性,焦点态也显示  |
| 2.4  | 倒计时微标签:`等 8min` 用红/橙 8px 标签;>10min 入场闪烁一次  | `OpponentCard.vue`、`app.css`                                | 用 `animation: pulse 0.6s 1` |

**里程碑**:用户能在不点开聊天的前提下完成 80% 的回价/分配动作。

## Phase 3 · 布局结构调整(预计 2 天 / 4 个 commit)

涉及 grid 结构和过滤态条件渲染,风险中,需要拖拽与响应式回归。

| 序号 | 任务                                                         | 文件                                     | 备注                           |
| ---- | ------------------------------------------------------------ | ---------------------------------------- | ------------------------------ |
| 3.1  | 行情两栏自适应:`grid auto-fill minmax(320px, 1fr)`,≥720px 双列 | `MarketPanel.vue`(列表容器)、`app.css`   | 卡片高度需收敛到 ≤ 120px       |
| 3.2  | 过滤栏与状态合并:`未回复/已回复/全部` + `1级/2级` 合并 segmented;空过滤态隐藏 `当前过滤:全部对手` | `MarketFilterBar.vue`、`MarketPanel.vue` | 释放 36px 给卡片               |
| 3.3  | 图例移至过滤栏右侧灰字;footer 仅保留加载状态                 | 同上                                     | 删除底部 `暖色底=未回复...` 行 |
| 3.4  | 视图切换 segmented:`押券视图 / 期限视图` 合并 `全部` chip 同行;`cellLegend` 改右上角 `?` 气泡 | `TaskOverviewMatrix.vue`                 | 减少一行高度                   |

**里程碑**:行情同屏可见 6+ 张,矩阵抬头压缩 ~24px。

- **数据缺口**:1.4 / 2.1 需要确认 `allocated` 已分金额是否在 `useTaskOverviewMatrix` 输出里;若缺,加 0.5d 数据补全。
- **响应式回归**:3.1、3.3 需在 1280 / 1440 / 1920 三档下手测,确认 [app.css:2689 / 2894](https://claude.ai/epitaxy/newworkspace/trading-workbench-vue/src/styles/app.css:2689) 两段断点不冲突。
- **拖拽边界**:Phase 1/3 后矩阵列数/单元格宽度变化,需要重新校验 [App.vue:55-65](https://claude.ai/epitaxy/newworkspace/trading-workbench-vue/src/App.vue:55) 的 `MATRIX_MIN=360` 是否还合理,可能调到 320。
