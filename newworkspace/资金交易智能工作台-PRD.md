## 1. 产品概述

### 1.1 产品定位

资金交易智能工作台是面向资金交易员的单屏一体化交易工作台。它以“任务”为核心，将交易单台账、投研判断、行情报价、私聊成交与分配回写整合在同一屏幕，并由 AI 贯穿“解析报价、匹配机会、辅助分配、提示决策、跟踪进度”的交易闭环。

核心闭环：

```text
判断方向 → 发现行情机会 → 私聊成交 → 快捷/矩阵分配 → 回写任务台账
```

### 1.2 目标用户

主要用户：资金交易台交易员。

典型工作特征：

- 高频处理来自不同对手方的私聊询价、报价与成交确认；
- 需要持续盯住账户指令缺口、保本利率、可成交报价和待分配余额；
- 核心目标是在满足保本、准入、额度、质押、合规等约束下，将各账户“未出金额”尽快做到 0；
- 操作节奏快，不适合跨多个系统反复切换、复制和人工录入。

### 1.3 核心价值

| 价值 | 说明 |
|---|---|
| 任务驱动 | 左栏交易单台账常驻，账户缺口始终可见，所有行情与分配围绕任务闭环 |
| 行情与账户联动 | 点击账户后，右栏自动筛选和高亮可满足该账户的报价 |
| 私聊结构化 | AI 将自然语言私聊解析为结构化行情、聊天摘要和成交信息 |
| 成交即分配 | 成交后优先在聊天弹窗内完成快捷分配，复杂场景进入全屏矩阵 |
| 防遗漏 | 未分余额进入左栏待分配额度池，避免成交后无人处理 |
| 高频友好 | 三栏单屏、高密度展示、短路径操作、实时更新但不覆盖编辑中输入 |

### 1.4 产品目标

P0 目标：

- 支持交易员在 1920×1080 单屏内完成任务查看、行情筛选、聊天跟进、成交分配和台账回写；
- 将“账户缺口”和“可成交行情”直接联动，减少人工对照；
- 成交后提供快捷分配与全屏矩阵两种处理路径；
- 建立实时行情、聊天、台账、待分配的统一刷新与冲突保护机制；
- 明确 AI 与后台接口在报价解析、分配候选、准入额度校验、台账回写中的职责。

非目标 / 本期不展开：

- 不在行情表内提供报价修正入口；
- 不做强制独立分配浮层；
- “新增需求”“广播”按钮仅占位，不实现完整业务逻辑；
- 不在快捷分配弹窗中展示不可分配账户和不可分原因；本期全屏矩阵也不展开不可分原因，只处理完整账户 × 对手分配视图；
- 不在右栏展示完整长聊天流，完整聊天由聊天弹窗承载。

## 2. 业务问题与机会

### 2.1 现状痛点

| 痛点 | 现状表现 | 影响 |
|---|---|---|
| 任务与行情割裂 | 指令台账在 Excel 或独立系统，报价在行情看板 | 交易员需要人工反复对照账户缺口和市场报价 |
| 私聊与系统割裂 | 报价、还价、done 分散在外部聊天工具 | 成交后需要人工结构化录入，容易遗漏 |
| 投研难以落到动作 | 投研观点只是参考信息 | 难以直接作用到报价判断和分配策略 |
| 分配链路重 | 成交后跨账户拆分复杂 | 容易出现未分余额、超额、未准入、保本不满足等风险 |
| 高频场景抗干扰弱 | 弹窗、切页、人工录入过多 | 操作节奏被打断，关键机会可能错过 |

### 2.2 解决思路

- 以左栏“任务台账”为核心，右栏“行情报价 / 历史聊天对手”为主战场，中栏“投研 / 行情数据摘要”为弹性参考区；
- 通过 AI 将私聊消息实时结构化，进入行情报价盘和聊天摘要；
- 通过账户点击联动，让交易员从“我要完成什么”直接看到“市场上哪些可以做”；
- 通过快捷分配处理轻量成交，通过全屏矩阵处理跨账户、跨对手、多笔成交的复杂分配；
- 通过待分配额度池兜底未处理余额，形成交易闭环。

## 3. 用户场景

### 3.1 场景一：交易员查看今日任务缺口

交易员进入工作台，左栏展示当前账户/产品上下文下的交易单台账。交易员快速查看每个账户的期限、未出金额、完成度与保本利率，并优先关注保本预警与大额未出账户。

成功结果：交易员能够在不切页的情况下知道今日主要缺口在哪里。

### 3.2 场景二：从账户缺口匹配可做行情

交易员点击某个未出账户行，系统在右栏行情报价中筛选并高亮满足该账户要求的报价，包括利率不低于保本、品种/期限匹配、质押和账户要求匹配。

成功结果：交易员能直接从任务行定位可成交机会。

### 3.3 场景三：从行情进入聊天并完成成交

交易员点击右栏行情单元格或历史聊天对手，打开聊天弹窗。弹窗顶部展示 AI 解析出的报价摘要；交易员在弹窗中继续询价、回复，并在 AI 识别 done 或人工确认后生成成交摘要。

成功结果：交易员在上下文内完成从行情到成交的动作。

### 3.4 场景四：成交后快捷分配

成交确认后，聊天弹窗下半部展开快捷分配面板，只展示当前成交可直接分配的账户。系统可自动给出分配建议，交易员可手动修改金额，保存后回写左栏台账。

成功结果：轻量成交无需离开聊天上下文即可完成分配和台账更新。

### 3.5 场景五：复杂分配进入全屏矩阵

当一笔成交需要跨多个账户、多笔对手额度或查看完整账户字段时，交易员点击“转全屏矩阵”。矩阵作为左侧任务面板的扩展形态展开，左侧冻结账户字段，顶部冻结对手额度，交易员按格子录入分配金额，也可使用 AI 自动分配草案。

成功结果：复杂拆分在一个完整矩阵中完成，并可保存回写台账。

### 3.6 场景六：未分余额进入待分配池

如果快捷分配或矩阵分配后仍有余额，交易员可挂入左栏待分配额度区。待分配条目显示对手、金额、成交利率、时间、方向和来源，并可再次打开聊天或全屏矩阵处理。

成功结果：未处理成交不丢失，可继续跟进。

## 4. 信息架构与布局

### 4.1 页面结构

```text
顶栏：工作台标题 / DR007 / 资金情绪四值 / 松紧结论 / 账户切换 / 日期 / 通知

左栏：任务
  - 试算利率
  - 交易单台账精简视图
  - 待分配额度区

中栏：投研 / 行情数据摘要
  - 投研：资金面情绪、AI 投研观点
  - 基准价格：大行价格、交易所回购、XREPO、NCD
  - 走势统计：加权价格走势、匿名成交走势、机构分期限统计

右栏：非银报价盘 / 历史聊天对手
  - 行情层级与方向上下文
  - 筛选条
  - 上半区行情报价
  - 下半区历史聊天对手

浮层：
  - 中等浮框
  - 聊天弹窗
  - 全屏分配矩阵
  - 通知面板
```

### 4.2 三栏宽度调整

三栏采用“默认比例 + 用户自由拖拽调整”的布局策略。默认推荐比例为左栏任务约 22%、中栏投研 / 行情约 28%、右栏行情 / 聊天约 50%，但该比例不是硬约束。

| 栏位 | 默认比例 | 调整规则 | 说明 |
|---|---:|---|---|
| 左栏任务 | 约 22% | 可拖拽调整 | 承载任务台账与待分配额度，调整后仍需保证核心列可读 |
| 中栏投研 / 行情 | 约 28% | 可拖拽调整 | 承载投研与行情数据摘要，过窄时进入紧凑态 |
| 右栏行情 / 聊天 | 约 50% | 可拖拽调整 | 承载行情报价与历史聊天对手，是高频主战场 |

调整规则：

- 左 / 中 / 右栏之间提供垂直拖拽分隔条；
- 用户可自由拖拽三栏宽度，系统不按固定优先级强行回弹；
- 每栏应设置最小可用宽度，防止核心内容完全不可读，具体最小值由设计与前端实现确认；
- 拖拽结果在当前用户维度本地持久化；
- 双击分隔条可恢复默认比例；
- 全屏分配矩阵打开时，矩阵作为左侧任务面板的扩展形态展开，不作为独立表格页面；展开后的矩阵不受当前三栏宽度影响。

### 4.3 响应与缩放

- 目标屏幕为 1920×1080 单屏；
- 支持 80%–150% 缩放；
- 缩放或空间紧张时，优先尊重用户已拖拽设置；若低于最小可用宽度，则对应栏进入紧凑态；
- 极限态下，中栏收为窄边图标条，点击后临时滑出数据摘要浮层；
- 全屏分配矩阵打开时，中栏可折叠让位，矩阵保持左侧任务视图扩展的业务语义。

## 5. 功能需求

### 5.1 顶栏

#### PRD-FR-001 全局基准信息展示

顶栏应常驻展示工作台名称、DR007、资金情绪四值、松紧结论、当前账户/产品、日期与通知入口。

验收标准：

- 用户在任意三栏状态下均可看到 DR007、资金情绪四值与松紧结论；
- 资金面指标更新时有短暂闪烁反馈；
- hover 资金面指标时展示口径说明与更新时间；
- 点击资金面指标本身不跳转，详情通过中栏资金面情绪摘要卡查看。

#### PRD-FR-002 账户 / 产品上下文切换

用户可通过顶栏切换当前账户/产品上下文。切换后左栏、中栏、右栏按新上下文刷新。

验收标准：

- 点击账户入口可展开下拉选项；
- 选择新账户后，三栏数据刷新；
- 若存在未保存编辑，切换前必须二次确认；
- 下拉支持键盘上下移动、Enter 选择、Esc 收起。

#### PRD-FR-003 通知入口

顶栏通知入口用于承载 AI 待决策、成交待分配、报价异动、系统提示等消息。

验收标准：

- 通知角标显示未读数量；
- 打开通知面板后可查看通知分类和列表；
- 点击通知可跳转到对应位置，如聊天弹窗、待分配条目或 AI 待决策项；
- 打开通知后未读数按产品定义清零或部分清零，具体口径待确认。

### 5.2 左栏任务

#### PRD-FR-010 试算利率编辑

左栏顶部展示试算利率，用户可点击编辑。提交后，系统重算所有账户的保本金额和保本利率。

验收标准：

- 点击试算利率数值后进入编辑态并全选当前值；
- 只允许输入数字和小数点；
- 非法输入标红，并阻止提交；
- Enter 或失焦提交，Esc 取消；
- 提交后台账相关保本字段刷新并闪烁提示。

#### PRD-FR-011 交易单台账精简视图

左栏展示交易指令执行台账精简视图，至少包含账户、期限、未出、完成度、保本利率。

验收标准：

- 未出金额作为核心数字突出展示；
- 完成度展示已出 / 指令的百分比；
- 保本利率触及或超过当前可得报价时出现预警样式；
- 已完成账户仍保留在列表中，但整行淡化；
- 账户较多时台账区可纵向滚动。

#### PRD-FR-012 账户行选择与行情联动

用户点击台账账户行后，右栏行情和历史聊天对手筛选并高亮满足该账户要求的内容。

匹配条件至少包括：

- 报价利率不低于账户保本利率；
- 品种 / 期限匹配；
- 质押要求匹配；
- 账户性质要求匹配；
- 准入与额度校验结果满足要求（若接口已接入）。

验收标准：

- 单击账户行进入唯一选中态；
- 再次单击已选中行取消选中；
- 选中时右栏匹配行情高亮，未命中行情可置灰；
- 相关历史聊天对手同步高亮或筛选；
- 本期不要求通过键盘打开矩阵；后续可再补充账户行键盘操作。

#### PRD-FR-013 台账手动排序

用户可拖拽账户行调整任务顺序。系统不自动排序。

验收标准：

- hover 行时显示拖拽手柄；
- 拖拽时其他行显示让位预览；
- 松手后提交新顺序；
- 排序结果应按产品定义持久化，持久化范围待确认。

#### PRD-FR-014 待分配额度区

左栏下方展示已成交但尚未完全分配的额度池。

字段至少包括：

| 字段 | 说明 |
|---|---|
| 对手 | 成交对手方 |
| 金额 | 未分余额 |
| 成交利率 | 成交价格 |
| 时间 | 成交或挂入时间 |
| 品种 / 方向 | 如逆回购 / 正回购 |
| 来源 | 快捷分配剩余 / 手动挂起 |
| 操作 | 分配 |

验收标准：

- 有待分配条目时显示区域，无条目时隐藏区域；
- 区块头展示待分配笔数和汇总金额；
- 新条目到达后从顶部插入并短暂高亮；
- 点击条目主体打开对应聊天弹窗；
- 点击“分配”打开全屏分配矩阵，并预置该笔待分配额度；
- 条目分配完成后淡出移除。

### 5.3 中栏投研 / 行情数据摘要

#### PRD-FR-020 中栏数据摘要区

中栏不只是详情入口，而是“可直接阅读的数据摘要区”。默认态下，每个子模块以摘要卡片呈现，必须展示关键数据值，交易员不打开浮框也能获得判断依据；点击模块仍可打开中等浮框查看完整图表、列表或矩阵。

模块清单与默认展示内容：

| 分组 | 模块 | 默认态必显数据 | 点击后展示 |
|---|---|---|---|
| 投研 | 资金面情绪 | DR007、资金情绪四值、松紧结论、更新时间 | 情绪明细、指标口径、历史走势 |
| 投研 | AI 投研观点 | 方向判断、建议 bp、置信度或关键依据摘要 | 完整观点、依据、风险提示 |
| 基准价格 | 今天大行价格 | 核心期限报价小表、隔夜 / 7D 代表值、涨跌 | 大行各期限完整报价表 |
| 基准价格 | 交易所回购 | GC / R 核心期限代表值、成交量、涨跌 | GC / R 系列完整列表 |
| 基准价格 | XREPO | 代表期限挂单利率、金额、可点击量、更新时间 | 完整挂单、可发送操作 |
| 基准价格 | NCD 同业存单 | 代表期限 / 评级、最新收益率、一级 / 二级摘要、趋势变化 | 一级 / 二级切换、趋势图、完整表格 |
| 走势统计 | 加权价格走势 | 代表期限最新加权价、涨跌、成交量或迷你趋势 | 多周期价格线 + 成交量 |
| 走势统计 | 匿名成交走势 | 日内加权均价、成交量、相对均线偏离或迷你趋势 | 日内加权利率 / 成交量图 |
| 走势统计 | 机构分期限统计 | 当前期限、当前指标、领先机构类型 / 最高最低摘要 | 机构类型 × 期限 × 指标矩阵 |

验收标准：

- 每个模块默认态至少展示 1 个主指标或主结论，以及不少于 2 个支撑数据值；
- 每个模块默认态必须展示更新时间、数据日期或数据状态之一，避免用户无法判断数据新鲜度；
- 任一模块在宽松态和紧张态下均不得退化为纯入口名称；
- 数据暂缺、延迟或取数失败时，卡片保留固定位置并展示明确状态，不因数据缺失导致布局跳动；
- 模块数据更新时，只对变化字段进行短暂闪烁，并用涨跌色提示方向；
- 单击模块任意区域或放大图标打开中等浮框；
- 中栏在紧张宽度下优先保留模块名称、主指标和最关键支撑数据；
- 中栏极窄态可收缩为图标 / 短标签，但滑出层中仍展示关键数据值和更新时间 / 状态，而不是纯入口名称；
- 中栏摘要不得复制右栏完整行情表，只展示辅助判断所需的关键数据。

#### PRD-FR-021 中等浮框

用户点击中栏数据模块后，在中栏区域上层打开中等浮框，展示完整图表、列表或矩阵。浮框用于承载摘要卡片放不下的证据、口径、筛选与完整数据。

验收标准：

- 浮框不遮挡右栏行情 / 聊天面板；
- 同时只存在一个中等浮框；
- 多次打开不同模块时替换当前浮框内容；
- 浮框标题区展示模块名称、当前数据上下文和更新时间 / 数据状态；
- 浮框内支持 tab / 周期切换；
- 点击遮罩、关闭按钮或 Esc 关闭；
- 浮框打开时焦点锁定在浮框内。

#### PRD-FR-022 中栏弹性收缩

系统根据可用宽度自动收缩中栏。

验收标准：

- 宽松态展示模块名称、关键数据值和辅助摘要；

- 极限态展示窄边图标条；

- 全屏分配矩阵打开时中栏可折叠让位。

### 5.4 右栏行情 / 历史聊天对手

#### PRD-FR-030 行情方向与层级切换

右栏提供正回购 / 逆回购方向切换，以及 1 级 / 2 级行情层级切换。

验收标准：

- 正回购 / 逆回购为互斥上下文；

- 行情表内部不展示方向字段；
- 1 级 / 2 级切换后行情整体刷新并显示当前态。

#### PRD-FR-031 行情筛选

右栏筛选条支持期限、发送机构、金额区间、利率区间、质押要求、限户要求、仅看相同交易对手等过滤。

当前筛选枚举先支持一部分，后续可由业务配置继续补充：

| 筛选项 | 当前枚举 |
|---|---|
| 质押 / 品类要求 | 利率、地方、CD、信用 |
| 限户要求 | 专户、公募 |

验收标准：

- 期限标签单选，再次点击取消；
- 发送机构搜索过滤行情发送机构，并同步过滤历史聊天对手；
- 金额和利率区间仅允许数字；
- 质押 / 品类要求支持多选筛选；
- 限户要求支持多选筛选；
- 质押 / 品类要求和限户要求可组合使用；
- 筛选条件同时影响上半区行情报价和下半区相关历史聊天对手；
- 用户可一键清空全部筛选条件；
- 下限大于上限时标红并阻止提交；
- 仅看相同交易对手时，只保留与当前账户或当前聊天上下文相关的发送机构 / 对手。

#### PRD-FR-032 行情报价表

右栏上半区按分组展示结构化行情。右栏行情报价区与历史聊天对手区默认高度比例为 1:1。

分组：

- 利率地方；
- 存单商金；
- 信用。

表格字段：

| 字段 | 说明 |

| 状态 | 最优 / 次优 / 普通，由 AI 自动标注 |

| R001 / R007 / R014 / R021 / R028 | 单元格展示“利率 / 金额”，无报价显示 `--` |

| 限户要求 | 专户、公募等，后续可补充 |

验收标准：

- 每个分组展示金额总量和利率均价；

- hover 行展示发送机构全称；
- hover 期限单元格展示限户、押券、原始消息摘要；
- 单击期限单元格打开或定位聊天弹窗；

#### PRD-FR-032A 右栏报价统计小页

右栏顶部操作区在 `1级 / 2级 / 下载` 同组内增加 `统计` 入口，建议排列为 `1级 / 2级 / 统计 / 下载`。统计页用于观察持续新增报价在日内时间轴上的利率与数量变化，打开后替换右栏上半区行情表，下半区历史聊天对手保持可见。

统计对象为当前筛选条件下的结构化报价流水，每条报价至少包含：获取时间、期限、利率、金额、机构、方向、分组。统计页跟随右栏当前筛选条件，包括层级、期限、金额区间、利率区间、账户匹配等。

统计口径：

| 统计轴 / 维度 | 说明 |
|---|---|
| 横坐标 | 报价获取时间，按时间桶聚合，可先按原始秒级时间展示，后续支持 1 分钟 / 5 分钟聚合 |
| 统计维度 | 期限：R001 / R007 / R014 / R021 / R028 |
| 总计 | 每个时间点合并所有期限后的总计指标 |

图表展示建议：

- 主图为时间横轴组合图；
- 总计均价作为主线展示；
- 各期限均价作为彩色细线展示；
- 每个时间点的报价笔数用底部小柱展示；
- 每个期限在该时间点的最高 / 最低利率用竖向范围线展示；
- 顶部展示总报价笔数、总金额、总均价、最高 / 最低利率四个摘要指标；
- 右侧或下方展示期限汇总表：期限、报价笔数、均价、最高 / 最低、总金额。

验收标准：

- 点击 `统计` 后右栏上半区切换为统计页，点击关闭可返回行情表；
- 统计页不影响下半区历史聊天对手；
- 统计结果随右栏筛选条件实时刷新；
- 新报价追加后，对应时间点和期限维度自动更新；
- 无报价时展示空态，保留当前筛选条件；
- 1366 宽度下统计页内部可横向滚动，不挤压左栏和中栏。

#### PRD-FR-033 右栏上下比例调整

#### PRD-FR-034 历史聊天对手索引

右栏下半区展示历史聊天对手索引，不展示完整聊天流。

每条记录固定两行：

验收标准：

- 弹窗不遮挡左栏与中栏关键区域；

#### PRD-FR-041 消息流与输入

聊天弹窗中部展示私聊消息流，底部提供输入与发送。

验收标准：

#### PRD-FR-042 成交确认

系统在 AI 识别成交或交易员人工确认 done 后，在聊天弹窗中展示成交摘要。

字段：

操作：

| 操作 | 说明 |

- 分配金额不得超过账户可分上限；
- 分配金额不得超过本笔成交剩余金额；
- 勾选账户参与分配，取消勾选时清空该行分配金额；
- 保存后回写左栏台账；
- 若仍有余额，可挂入待分配；
- 点击“转全屏矩阵”时，矩阵应自动带入当前成交的对手、期限、成交总额、成交利率、方向、已填分配金额、待分余额和 AI 草案。

待确认方案为 `multi`：允许 N 个弹窗平铺或堆叠，各自独立。

验收标准：

- P0 默认按 `replace` 实现；
- 代码或配置层预留 `multi` 扩展点；
- 切换策略不影响聊天消息、成交确认和快捷分配数据。

### 5.6 全屏分配矩阵

#### PRD-FR-050 矩阵打开与关闭

全屏分配矩阵用于完整账户 × 对手额度分配，是左侧任务面板的扩展形态，不是独立表格页面。它从左栏任务、待分配或聊天快捷分配进入，展开后承载左栏台账的完整视图与对手分配明细。

打开来源：

- 左栏台账行双击 / Enter；
- 左栏待分配“分配”；
- 聊天快捷分配“转全屏矩阵”；
- 台账“展开”入口。

验收标准：

- 打开后以左侧任务面板扩展形态呈现，可扩展到工作区宽度；
- 中栏可折叠让位，但矩阵业务归属仍属于左侧任务视图；
- 矩阵层级高于聊天弹窗；
- 收起时自动保存当前矩阵草案并返回常态三栏；
- 工具栏需要提供当前成交摘要、AI 自动分配、清空、保存分配、新增需求、广播、收起入口；
- “新增需求”“广播”本期只保留入口，不实现业务逻辑。

#### PRD-FR-051 矩阵结构

矩阵包含左侧冻结账户字段、金额汇总字段、对手维度、分配格子、总额行、差额行和底部总计行。对手维度采用两级表头：一级为机构 / 对手方，二级为该机构下的期限 / 成交列，成交列以期限、成交时间或成交序号区分。

| 维度 | 内容 |
|---|---|
| 左侧冻结列 | 选择、账户ID、账户简称、期限、指令、金额分组（总额 / 差额 / 完成度 / 待分） |
| 金额分组 | 总额、差额、完成度、待分，按账户行实时汇总 |
| 行 | 每行代表一个账户指令，可勾选后参与批量分配 / 自动分配 |
| 一级列 | 机构 / 对手方，用于聚合同一机构下的多笔成交 |
| 二级列 | 成交批次列，每列代表一笔成交额度，可用期限、成交时间或成交序号辅助识别，展示期限、总额、成交利率、方向等摘要 |
| 格子 | 账户 × 机构成交批次 的分配金额 |
| 总额行 | 每个二级成交列的成交总额，位于账户明细行上方 |
| 差额行 | 二级成交列分配后的剩余，位于总额行下方 |
| 底部总计行 | 汇总指令、总额、差额、完成度、待分和各机构成交批次列分配金额 |
| 备注 / 限制 | 通过悬浮说明或行详情展示账户分配限制和说明，不挤占主表左侧固定列 |

验收标准：

- 左侧选择、账户ID、账户简称、期限、指令和金额分组横向滚动时固定；
- 顶部机构行、二级成交批次列、总额行、差额行纵向滚动时固定；
- 中间格子区支持横向和纵向滚动；
- 支持 20+ 对手列；
- 支持大量账户行，滚动时关键上下文不丢失；
- 同一机构的多笔成交应靠近展示，归在同一个机构一级目录下；
- 同一机构、同一期限再次成交时也新增二级成交列，不与已有列合并；`R001` / `R007` 只是成交列的期限属性，不等同于唯一列定义。

影响范围：

- 左栏台账的精简视图不变，完整矩阵通过左侧任务面板扩展视图承载；
- 左侧冻结列、顶部机构行、总额行、差额行和底部总计行需要统一冻结与滚动规则；
- 矩阵数据模型需要支持机构一级目录、二级成交列、账户行汇总和底部总计回写；
- 快捷分配弹窗仍保持轻量，不承担完整矩阵的列级展示与汇总计算。

#### PRD-FR-052 聊天成交带入矩阵

从聊天成交或快捷分配进入全屏矩阵时，系统应自动生成或定位对应机构一级目录，并在该机构下新增一列二级成交列。即使同一对手、同一期限已存在成交列，也按新成交新增列，避免不同成交批次被合并。

自动带入字段：

| 字段 | 带入位置 |
|---|---|
| 对手 / 机构 | 矩阵顶部一级机构目录 |
| 期限 | 二级成交列表头 |
| 成交总额 | 该二级列总额行 |
| 成交利率 | 二级成交列表头或 tooltip |
| 方向 | 二级成交列表头或筛选上下文 |
| 已填快捷分配金额 | 对应账户 × 该成交列的格子 |
| 待分余额 | 该二级列差额行 |
| AI 建议分配草案 | 对应账户格子预填或草案态展示 |

验收标准：

- 点击聊天弹窗“转全屏矩阵”后，矩阵自动滚动或定位到该机构目录；
- 若机构不存在，则新增机构一级目录；
- 若机构已存在，则在该机构下新增二级成交列；
- 同一机构、同一期限再次成交时仍新增二级列，并通过时间或序号区分；
- 快捷分配中已填写的金额必须带入矩阵格子；
- 二级成交列的总额、差额、期限、成交利率、方向应自动填充；
- 用户进入矩阵后可继续手工修改分配格子。

#### PRD-FR-053 矩阵格子编辑

用户可在矩阵格子中手动录入分配金额。

验收标准：

- 单击或双击格子进入编辑态；
- 只允许数字和小数点；
- 输入后实时刷新账户行总额、差额、完成度、待分；
- 本期暂不要求矩阵方向键、Enter、Tab、Esc 等键盘操作；
- 本期暂不要求矩阵编辑态的实时推送冲突保护。

#### PRD-FR-054 矩阵校验与保存

矩阵支持横向对手额度校验、纵向账户金额汇总和账户未出预览。

校验规则：

| 场景 | 规则 |
|---|---|
| 对手列差额 = 0 | 该机构成交批次列已分完 |
| 对手列差额 > 0 | 允许保存，表示该机构成交批次列仍有未分额度 |
| 对手列差额 < 0 | 超分配，高亮提示，不阻断自动保存 |
| 账户行总额 | 等于该账户在所有机构成交批次列中的分配金额之和 |
| 账户行差额 / 待分 | 差额 = 指令 - 总额；待分 = max(差额, 0) |
| 账户行完成度 | 完成度 = 总额 / 指令，随分配额实时更新 |
| 自动分配覆盖手填格 | 必须二次确认 |

验收标准：

- 编辑格子后实时重算该对手列总额行、差额行；
- 编辑格子后实时刷新账户行总额、差额、完成度、待分；
- 手动保存或收起矩阵时自动保存当前草案并回写左栏台账；
- 保存后刷新总额、差额、完成度、待分、保本测算和左栏台账；
- 允许差额非 0 保存；
- “新增需求”“广播”按钮本期置灰或提示“暂未开放”。

#### PRD-FR-055 AI 自动分配

系统可在快捷分配和全屏矩阵中生成 AI 分配草案。

主干逻辑：

1. 调用后台接口校验账户准入白名单、剩余可投额度、账户要求与质押要求；
2. 剔除保本利率高于成交利率的账户；
3. 根据业务优先级对候选账户排序；
4. 按优先级和剩余额度生成分配金额；
5. 在快捷分配中只填入可分配账户；本期全屏矩阵不展示不可分账户及原因。

验收标准：

- 快捷分配中 AI 自动分配只填入可分配账户；
- 本期全屏矩阵不展示不可分原因；
- AI 草案可被人工修改；
- AI 覆盖已手填数据前必须二次确认；
- 保存前仍以后台校验结果为准。

- 行情报价、聊天摘要、台账数值、待分配条目、聊天消息均支持实时推送；
- 数据更新时对应行或单元格闪烁；
- 用户正在编辑的关键输入框原则上不被推送覆盖；本期矩阵格子的实时推送冲突保护暂不纳入范围；
- 编辑控件失焦或提交后恢复同步；
- 底层三栏在浮层打开时仍继续刷新，不冻结。

| 时间 | `HH:mm:ss` |
| 日期 | `YYYY-MM-DD` |
| 完成度 | 百分比整数或 1 位小数 |

## 7. 业务规则

### 7.1 账户与行情匹配

账户匹配行情时，应至少满足：

- 方向一致；
- 期限兼容；
- 成交利率满足账户保本约束；
- 限户要求满足账户性质；
- 押券要求满足账户可接受质押品；
- 账户准入和剩余额度校验通过。

### 7.2 快捷分配

- 快捷分配只处理当前聊天中的一笔成交；
- 快捷分配只展示可分配账户；
- 不可分原因不在弹窗中展示；
- 分配金额不得超过账户可分上限；
- 分配金额不得超过本笔成交剩余金额；
- 允许部分保存；
- 未分余额可挂入待分配。

### 7.3 全屏矩阵分配

- 矩阵用于处理完整账户 × 对手分配，是左侧任务面板的扩展视图；
- 最左侧冻结列固定为选择、账户ID、账户简称、期限、指令和金额分组；
- 对手列采用机构一级目录 + 成交二级列；
- 二级列以成交批次为准，期限只是列属性之一，同一机构、同一期限再次成交时不合并；
- 顶部总额行、差额行和底部总计行均为只读计算结果；
- 同一机构的多笔成交靠近展示，归在同一机构一级目录下；
- 同一机构、同一期限再次成交时新增二级成交列，不合并到已有列；
- 格子金额可手动录入，AI 草案仅作为辅助；
- 允许留差额保存；
- 差额小于 0 高亮提示，不阻断保存；
- 收起矩阵时自动保存当前草案；
- 保存后必须回写左栏台账；
- 本期全屏矩阵不考虑不可分账户和不可分原因展示。

### 7.4 成交与缺口

当前来源文档约定：成交量不会超过总缺口，不出现超额场景。

待确认：如果实际业务出现超额成交，应阻断、允许挂起，还是进入异常处理队列。

### 7.5 未保存编辑保护

以下场景需要二次确认：

- 切换账户 / 产品上下文时存在未保存编辑；
- 自动分配准备覆盖手填格子；
- 关闭聊天弹窗时快捷分配未保存。

## 8. 非功能需求

### 8.1 可用性

- 高频操作不依赖 hover 才出现关键信息；
- 常用路径不超过三步：看缺口 → 找行情 → 打开聊天 / 分配；
- 关键信息密度高，但输入、按钮、状态必须可辨识；
- 所有浮层支持 Esc 关闭，并按层级逐层关闭。

### 8.2 性能

建议目标，需与技术和业务确认：

| 指标 | 建议目标 |
|---|---|
| 行情 / 聊天推送到前端可见 | P95 ≤ 1s |
| AI 报价解析出结构化结果 | P95 ≤ 2s |
| 快捷分配候选返回 | P95 ≤ 1s |
| 矩阵保存回写 | P95 ≤ 2s |
| 1920×1080 下滚动 / 输入 | 无明显卡顿 |

### 8.3 可靠性与降级

- 接口超时或失败时，应明确提示当前能力不可用；
- 准入 / 额度 / 合规校验失败时，不应静默保存；
- AI 自动分配失败时，用户仍可手动分配；
- 报价解析失败时，原始聊天仍可查看；
- 分配保存失败时，不应清空用户已填写草案。

### 8.4 审计与留痕

以下操作建议留痕，具体范围待确认：

- 成交确认；
- AI 分配草案生成；
- 人工修改分配金额；
- 保存分配；
- 挂入待分配；
- 自动分配覆盖手填数据；
- 账户准入 / 额度校验失败原因；
- 台账回写结果。

## 11. 风险与待确认事项

### 11.1 需要业务确认

| 编号 | 事项 | 影响 |
|---|---|---|
| Q1 | AI 分配优先级口径：保本紧迫度、完成度、缺口规模、账户权重如何排序 | 影响自动分配结果和交易员信任 |
| Q2 | 快捷分配可分账户筛选口径和可分上限计算公式 | 影响弹窗中展示哪些账户、可填多少金额 |
| Q3 | 账户准入 / 额度 / 质押校验时机：洽谈中预校验还是成交后校验 | 影响成交前提示和成交后阻断策略 |
| Q4 | 哪些限制可缓存，哪些必须实时查询 | 影响接口性能与合规风险 |
| Q5 | 接口超时或故障时，允许降级手动保存还是必须阻断 | 影响可用性与合规底线 |
| Q6 | 成交量超过总缺口时的处理方式 | 来源文档假设不超额，但真实业务可能需要兜底 |
| Q7 | 差额 > 0 保存后的状态：自动进入待分配、保留在矩阵，还是需要用户选择 | 影响待分配池口径；当前矩阵允许留差额并自动保存 |
| Q8 | 多会话策略最终采用单弹窗替换还是有限多弹窗 | 影响前端状态管理和交易员操作习惯 |
| Q9 | “人工确认 done”的入口、权限和留痕要求 | 影响成交确认可靠性 |
| Q10 | 通知角标清零口径：打开即清、逐条已读、还是处理后清 | 影响通知可信度 |
| Q11 | 金额展示单位统一用“亿”还是矩阵用“万元” | 影响输入、展示和校验精度 |
| Q12 | 新增需求 / 广播是否进入本期范围 | 影响排期和页面按钮状态 |

### 11.2 需要技术确认

| 编号 | 事项 | 影响 |
|---|---|---|
| T1 | 私聊数据来源与 IM 集成方式 | 决定聊天弹窗、消息流、解析服务的接入边界 |
| T2 | 行情实时推送协议与频率 | 决定前端刷新策略和性能压力 |
| T3 | 矩阵大数据量下的渲染方案 | 20+ 对手列和大量账户行可能需要虚拟滚动 |
| T4 | AI 解析结果修正机制 | 来源文档倾向行情只读，但解析错误如何处理待确认 |
| T5 | 台账回写事务一致性 | 分配保存、待分配余额、台账刷新需要一致 |
| T6 | 权限与审计系统是否已有统一能力 | 影响成交确认、分配保存、异常处理 |

### 11.3 主要风险

- AI 解析准确率不足会影响行情可信度；
- 自动分配算法如果口径不透明，交易员可能不敢使用；
- 准入、额度、合规接口若响应慢，会拖慢成交后分配；
- 高频推送与用户编辑冲突处理不当，会造成输入丢失；
- 全屏矩阵信息量大，若性能或冻结窗格体验不好，会影响复杂分配效率。
